### User
We're shipping a small internal tool. Coworker pinged me, "don't bother with the README, we need to move fast, people can just ask us." I am the person people will ask. Last time we skipped notes, I spent a week answering the same Slack thread. I don't want to be the blocker. I also don't want to be the tribal-knowledge vending machine. First time I'm going to push back instead of doing a secret README at 11 p.m.

### Assistant
Push back in the same channel they used, while the work is still small. Secret 11 p.m. docs train them that you'll absorb the cost.

"I'll do a short README. Fast for us this week is slow for everyone who asks later." If they want shorter, make it shorter. A page with what it is, how to run it, and who owns it is not a novel. Moving fast includes not becoming a help desk.

You are not the blocker. The missing page is. People can still ask you. They shouldn't have to ask you how to start the thing.

I will not invent your company's process. If you have a template, use it. If you don't, three headings are enough.

Are they senior to you, or a peer who just likes speed as a personality?

### User
Peer. Same title. They have a reputation for shipping. I have a reputation for "being thorough," which is code for slow. If I write the README they might still call it bureaucracy in standup.

### Assistant
Let them call it bureaucracy. You can still ship. Thorough is not a crime if the tool actually starts on someone else's laptop.

Do the README in the same PR as the code, not as a later chore. Later chores vanish. A PR that includes how to run it is just the work. In standup you can say "tool plus a one-pager so we're not the FAQ." That's a status, not a defense.

If they delete the file in review, comment why it stays: last time's Slack pile. One sentence. Don't write a manifesto about knowledge management. Manifestos confirm the "slow" story. A file with commands does not.

You can offer them the shortcut they actually want: "I'll write it. You don't have to. We still need it." Some speed people hate writing and will accept a page they didn't type. That's a win. You didn't become the 11 p.m. ghost. You made it visible.

### User
What if they say users are only the two of us so docs are wasted.

### Assistant
Then the README is still for future-you, vacation-you, and the person who joins in March. "Only us" is how tribal knowledge starts. If it's truly two people forever, the page takes fifteen minutes and you lose almost nothing. If it's not, you already know.

"Even if it's us, I want the start steps written so I'm not repeating them." That's your stake. You get to have one.

Ship the tool. Include the page. Don't secret-write it. Don't apologize for it in standup. Fast includes not answering the same question until you hate the tool you built.

### User
I put a one-page README in the PR. They commented "do we need this." Standup is in twenty minutes. I can feel myself writing a paragraph about tribal knowledge. Don't let me.

### Assistant
Reply in the PR, one sentence: "Yes. It's how to run it without asking us." Then you stop typing. If they resolve it with "later," you leave the file in and say in standup "README is in the PR so we're not the FAQ." That's status. Tribal-knowledge essays belong in a blog you will not write on company time.

If they still want it out to "move fast," ask them to own the Slack questions for two weeks. Some speed people suddenly like a page when the help desk has a name. If they agree to own the questions, you still keep the page. Their ownership is extra, not a substitute.

Twenty minutes: don't open a new draft. The page exists. The comment has a one-line answer. You ship the tool and the start steps together. Fast includes not answering the same thread until you hate the thing you built. You already knew that. The file is how you remember it in public.
