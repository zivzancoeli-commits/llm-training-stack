### User
We're shipping a form. Coworker said skip the labels and keyboard path "until later, we need the demo to look pretty." I can already see later meaning never. I am not the accessibility cop. I also don't want to demo a form nobody can tab through. Standup is in an hour. I need a pushback that isn't a manifesto.

### Assistant
Later is a parking lot with no lights. Put the labels in this demo.

"I'll do the pretty and the labels. Keyboard path is part of the form, not a phase." If they want less, you still keep labels. Labels are not decoration. A demo that only works with a mouse is a demo of a different product.

You don't need to be the cop. You need to refuse to delete the work you already know is required for a form. Manifestos in standup make people joke. A checklist in the ticket does not.

I will not invent your company's compliance program. If you have a standard, name it in the ticket, not as a threat. If you don't, "people have to tab" is still true.

Are they asking you to hide it for one slide, or to merge without it?

### User
Merge without it. The slide is the whole release. They said we can "sprinkle a11y on" after leadership claps. Leadership clapped last time and the sprinkle never happened.

### Assistant
Then you're not arguing a sprinkle. You're arguing a merge.

In the PR: labels and tab order stay. If they remove them in review, comment "this is the form working, not extra." One comment. Last time is a sentence you can use once: "We skipped this last release and it didn't come back." Don't tell the origin story of every miss.

Standup: "Form includes labels and keyboard access. I won't split that to after the demo." Status, not a TED talk.

If they override you with a merge anyway, you still file the follow-up ticket the same hour, assigned, with screenshots of the unlabeled fields. Tickets that exist the hour of the clap have a chance. Tickets from next quarter don't.

Pretty can be CSS. Pretty is not unlabeled inputs.

### User
If I die on this they'll say I slowed the demo.

### Assistant
A broken tab path is the slower demo when someone in the room can't use it. If they still say you slowed it, you shipped a form that works. That's the job.

Hour: PR complete enough to tab, standup sentence, no manifesto, follow-up ticket only if they strip it. You can like pretty. You can still type a label. Later is how last time's sprinkle died. Don't schedule a funeral for this one in advance. Just don't skip it.

### User
PR still has labels. They merged it with a comment "we'll pretty this after." Keyboard path is in. Demo is at 3. I will not write a slack essay when someone claps.

### Assistant
Don't. Claps can happen. The form can still tab. After is their word; the labels already shipped, which is the only after that counts.

If someone in the demo can't use it, that's a different problem you reduced. If everyone can, you still didn't skip it. Either way you don't need a manifesto in the clap thread.

Hour before standup already passed; 3 p.m. is just showing the thing. You can like pretty CSS later. You didn't die on a hill. You typed labels. Coworker can sprinkle nothing. The merge has the work. That's skip refused, demo intact, cop costume still in the drawer. Go to the demo with the form that works. If they strip labels in a follow-up commit, revert that part the same day and point at the merged PR. Sprinkle-after is how last time vanished. Don't wait for the clap to fade. Keep the ticket closed only if the code still has the labels at 3.
